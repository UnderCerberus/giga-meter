# ギガメーター 設計書

作成日: 2026-11-01
状態: 実装中。2026-11-02にユーザーの判断を反映(ウィジェット廃止、デザインA、アニメーション)

## 1. 目的

iPhoneのモバイル通信量を月単位で確認する個人用アプリ。

- 今月の使用量を見られる
- 月末時点の使用量の予測を見られる
- 毎月1日に今月分が0に戻り、計測し直す
- 月の途中でインストールしても、今月分の目安を見られる

## 2. 前提と制約

- iOSアプリは端末全体の通信履歴を読めない。読めるのは端末の累計カウンタのみ
- カウンタは再起動で0に戻る。32ビット値は約4.3GBで一周するという報告あり(現行iOSでは未確認)
- バックグラウンド更新の実行時刻はiOSが決める
- キャリアの計測値とは一致しない。無料扱いの通信、計測場所、締め日の違いが原因
- 開発環境はWindowsのみ。Macとシミュレータは使えず、動作確認は実機で行う

## 3. 対象外

- アプリ別、サイト別の内訳
- Wi-Fi通信量
- キャリアへのログインや自動取得
- データ容量の上限管理、残量表示、通知
- ホーム画面ウィジェット(無料Apple IDの署名にApp Groupの許可が無く、データを共有できないため)
- 1日以外のリセット日
- App Store公開
- 広告、課金、外部へのデータ送信

## 4. 全体構成

| 部品 | 役割 | iOS依存 |
|---|---|---|
| `GigaCore` | 増分計算、月次集計、初期値計算、月末予測 | なし |
| `ProbeKit` | カウンタと起動時刻の読み取り、診断用の生データ記録 | なし(Darwinのみ) |
| `MeterModel` | 読み取り、計算、保存を1回分実行する | アプリ層 |
| アプリ画面 | SwiftUIで表示、キャリア値の入力、診断 | あり |
| バックグラウンド更新 | `BGAppRefreshTask`で記録 | あり |

計算は`GigaCore`に集約し、実機なしで自動テストする。

計測の流れ:

1. アプリ起動、表示中の定期更新、下に引いて更新、バックグラウンド更新のいずれかで`MeterModel`を実行
2. `CounterReader`がインターフェース別、方向別の値と起動時刻を返す
3. `Ledger`が前回の値との増分を計算し、日別に配分して保存
4. 画面が`UsageSnapshot`を表示

## 5. 計測ルール

### 5.1 カウンタ

- `pdp_ip`で始まるインターフェースをモバイル通信として扱う
- 受信と送信を合算する
- 周回はインターフェース別、方向別に判定する
- 64ビット値を優先する。ただし増分の下位32ビットが32ビット値の増分と10MBを超えて食い違う場合は、64ビット値を信用せず32ビット値を使う

### 5.2 増分

前回の記録と比べて、次のとおり計算する。

| 状況 | 判定 | 増分 |
|---|---|---|
| 起動時刻が同じで値が増加または同じ | 通常 | 今回 − 前回 |
| 起動時刻が同じで値が減少 | 一周または個別リセット | 5.3参照 |
| 起動時刻が変化 | 再起動 | 今回の値。「未計測あり」を立てる |

起動時刻は時計補正で微小に変わることがあるため、60秒以内の差は同じ起動として扱う。

### 5.3 値が減少した場合

同じ起動中に値が減る原因は、4GB周回か、機内モードなどによるインターフェース別のリセットの可能性がある。後者を周回と誤判定すると、約4.3GBを過大に足してしまう。

- 64ビット値がある場合: 減少は個別リセットとして扱い、増分は今回の値
- 32ビット値のみの場合: 前回の値が2^31以上なら周回として「今回 + 2^32 − 前回」、未満なら個別リセットとして今回の値
- しきい値は実機の検証結果で見直す

### 5.4 区間の配分

- 日または月をまたぐ増分は、区間の長さに応じて時間で按分する
- 日付の区切りは端末のカレンダーとタイムゾーンで判定する
- 時計が戻された場合、増分は前回の時刻に計上する。増分は負にしない
- 24時間を超える区間は、日別グラフで「推定配分」として区別する

### 5.5 月次リセット

- 毎月1日0時を境に今月分を0から数える。処理は次の記録時に時刻を見て行うため、0時に動作しなくても正しく処理される
- 終了した月は補正値を含む合計値のみ履歴に残し、その月の区間データは削除する

### 5.6 単位

1GB = 1,000,000,000バイトとする。

## 6. 初回起動と補正

### 6.1 初回の今月分

再起動時刻で計算方法を変える。

| 状況 | 値 | 表示ラベル |
|---|---|---|
| 再起動が今月 | 再起動以降のカウンタ値 | 「再起動以降の実測」 |
| 再起動が先月以前 | カウンタ値 × (今月の経過時間 ÷ 再起動後の経過時間) | 「推定」 |

計算した値は今月の初期値として保存し、以後は増分を足す。この時点のカウンタ値を増分計算の基準にする。

32ビット値のみの場合、すでに周回している可能性があるため、どちらも「最低でもこの量」と表示する。

初回画面でキャリアの今月使用量の入力を促す。入力は省略できる。

### 6.2 キャリア値での補正

- 入力値と今月の合計の差を補正値として保存する
- 以後は補正後の値に増分を足す
- 再入力すると補正値を置き換える
- 補正はその月のみ有効で、翌月には引き継がない

## 7. 月末予測

月末予測 = 計測対象期間の1日平均 × その月の日数

計測対象期間の開始は次のとおり。

| 状況 | 開始 |
|---|---|
| 通常、「推定」、またはキャリア値を入力済み | 月初 |
| インストール月で「再起動以降の実測」のまま | 再起動時刻 |

- 計測対象期間が24時間未満の間は、予測を表示しない
- 推定値や「未計測あり」を含む場合は、予測にもその旨を表示する

## 8. 画面

### メイン画面

デザインは`docs/design/ui-concepts.html`の案A。黒地(#0B0D10)に黄緑(#C6F432)。

- 丸いメーター: 中央に今月の使用量と状態ラベル(実測、推定、キャリア値で補正済み、未計測あり)。濃い弧が使用量、薄い弧が月末予測、目盛りが先月の合計。全周は「月末予測、先月の合計、使用量」の最大値
- カード3枚: 月末予測、今日、先月
- 今月の日別グラフ: 未来の日はペース分を暗く表示。なぞると日ごとの値を表示
- 最終記録時刻、キャリア値の入力ボタン
- 下に引いて更新
- 診断画面: カウンタの生値、手動記録、CSV書き出し

### 初回画面

- アプリの計測方法と制約の短い説明
- キャリアの今月使用量の入力欄(省略可)

### アニメーション

- 起動時にメーターの弧を描き、数字をカウントアップする。続けて予測の弧を伸ばす
- カードは順に現れ、棒グラフは左から順に伸びる
- 弧の先端と今日の棒はゆっくり明滅する
- 値が更新されたら滑らかに変化する
- 更新やなぞる操作に触覚フィードバックを付ける
- iOSの「視差効果を減らす」がオンなら動きを省く

## 9. 検証版(最初に作る)

本体の前に、カウンタの実態を確かめる検証版を作る。カウンタの生値、起動時刻、記録の履歴を画面に表示し、CSVで書き出せるようにする。

| 確認項目 | 方法 | 影響する判断 |
|---|---|---|
| アプリからモバイル通信の値を読めるか | モバイル通信で数百MB通信し、増加を確認 | 不可なら開発を中止してユーザーに報告 |
| 32ビット値は4.3GBで一周するか | 4.3GB以上の通信で確認 | 周回補正の要否 |
| 64ビット値は正しいか | 32ビット値、設定アプリの増加量と比較 | 採用する値 |
| 機内モードや回線切替で値は変わるか | 切り替えの前後で比較 | 5.3のしきい値 |
| 再起動の検出 | 再起動の前後で比較 | 5.2 |
| バックグラウンド更新の頻度 | 記録の履歴で数日分を確認 | 再起動で失う量の見積もり |
| ウィジェットからの読み取り | ウィジェット更新時の記録を確認 | ウィジェットでの記録の可否 |
| 無料Apple IDでの動作 | ウィジェット、App Group、バックグラウンド更新を確認 | 配布方法 |

検証結果は`docs/probe-results.md`に残し、未確定の判断を確定させてから本体を実装する。

## 10. 保存とデータ共有

- 集計はアプリのDocumentsにある1つのJSONファイルに保存し、書き込みはアトミックに行う
- ファイルが壊れていた場合は別名で退避し、新規に開始する。画面に「記録をリセットした」と表示する
- 診断用の生データはJSON Linesで別ファイルに残し、5MBを超えたら消す
- 外部通信は行わない

## 11. ビルドと配布

- 言語はSwift、UIはSwiftUI、対応OSはiOS 17以降
- プロジェクト定義はXcodeGenの`project.yml`で管理する
- GitHub ActionsのmacOS環境でテストとビルドを実行し、未署名のIPAを成果物にする
- 最初の配布はSideloadlyと無料Apple IDで行う。7日ごとに再署名が必要
- 再署名の手間が問題になれば、有料のApple Developer登録に切り替える

ユーザーの操作が必要な項目:

- GitHubリポジトリの作成と公開範囲の確認
- SideloadlyへのApple IDの入力
- iPhoneでの開発元の信頼設定と検証作業

## 12. テスト

`GigaCore`の自動テストで次を確認する。

- 通常の増分
- 再起動で合計が減らず、「未計測あり」が立つ
- 周回補正と個別リセットの判定
- 日またぎ、月またぎの按分
- 1か月以上記録が空いた場合の配分
- 時計が戻された場合に増分が負にならない
- うるう年の2月を含む月の日数
- 初回の実測と推定の計算(例: 10月20日再起動、11月15日に13GB → 約7.5GB)
- キャリア値の補正、再入力、翌月のリセット
- 月末予測の計算と、24時間未満の非表示

## 13. 完了条件

- 自動テストがすべて成功する
- 検証版の結果を反映した本体がiPhone実機で動作する
- 月をまたいで今月分が0から始まり、先月の合計が履歴に残る
- 再起動後も今月の使用量が減らない
- 1か月使用し、キャリアの数字との差を記録する。差の目標値はこの結果を見て判断する
